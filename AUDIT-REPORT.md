## 4. Что пока не сделано

1. **Секретов нет и не было в архиве**: `.env` (`BOT_TOKEN`, `ADMIN_IDS`, `WEBAPP_URL`, `MANAGER_CHAT_ID`)
   не заполнен — бот в песочнице не подключается к Telegram, заказы через `/api/order` принимаются только
   после выдачи токена (шаблон — в `.env.example`).
2. **Пуш в GitHub**: `origin` настроен, но запись требует токен. Команда: `git push -u origin draft/sila-i-chest`,
   затем PR `draft/sila-i-chest → main` (см. `sila-i-chest/handoff/HOW-TO-PUSH.md`).
3. **Docker-образ не пересобран** — в песочнице нет docker. `Dockerfile`/`compose.yaml` не менялись с v0.2
   (добавлен только `.dockerignore`), риск минимален, но собрать стоит на машине с docker.
4. **Открытые находки аудита** (`audit/audit_poc.py`, сценарии на текущем коде всё ещё воспроизводятся):
   C/D — телефон сохраняется без согласия; E — чужой контакт принимается как свой;
   F — `/add` с битым `photo_url` портит `data/catalog.json` (бот не стартует после рестарта);
   G — реферал «захватывает» существующего пользователя; I — недоступное фото товара роняет карточку;
   J — рассылка синхронная в polling-потоке (~7 мин глухоты на 10 000 юзеров).
   Находка **H** (потеря `sendData` из inline-кнопки) закрыта в v2 через `POST /api/order`.
5. **Контент**: финальные кадры с Никитой — после его «ок» (см. `MESSAGE-FOR-NIKITA.md`);
   жетону нужна предметная съёмка 2000 px+ (README, раздел «Фото и картинки»).
6. Исходный архив `.zip` и промежуточные клоны удалены из воркспейса ради лимита места
   (проект занимает ~104 МБ); архив всегда доступен по ссылке релиза `v9-workspace-full`.

## 5. Как пользоваться

```bash
cd sila-i-chest-app
cp .env.example .env          # вписать BOT_TOKEN, ADMIN_IDS, WEBAPP_URL, MANAGER_CHAT_ID
python3 -m unittest test_bot  # 31 тест
python3 smoke_test.py         # сценарии без сети
python3 preview_server.py     # витрина: http://0.0.0.0:4173 (без токена — режим предпросмотра)
python3 bot.py                # продакшен: polling + витрина на :8080
```
