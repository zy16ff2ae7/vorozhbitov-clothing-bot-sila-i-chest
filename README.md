# ВОРОЖБИТОВ / SHOP 001

Telegram-магазин мерча и одежды: один бот + Telegram Mini App в общей стилистике бренда.
Витрина сделана mobile-first: её можно открыть в браузере для предпросмотра или подключить к кнопке Web App в Telegram.

## Что изменено

### Бренд и визуальная система

Концепция опирается на публичное описание Никиты Ворожбитова как автора контента про реальные жизненные истории, спорт, мотивацию и развитие. Визуальный перевод этого образа в магазин — тёмная утилитарная база, бетонная фактура, красный «сигнал», крупная типографика, короткие прямые CTA и ощущение ограниченного дропа.

В магазин намеренно не переносились шок-контент, политические сообщения, 18+ материалы, реклама казино или конфликтная риторика. Магазин остаётся про вещи, качество, размеры и заказ.

Перед публичным запуском нужно подтвердить у Никиты/правообладателя разрешение на название, логотип, фото, слоганы и продажу мерча. Сгенерированные изображения в `miniapp/assets/` — визуальные мокапы для прототипа, не фотографии реального товара.

### Telegram-бот

- `/start` — сегментация по интересу и главное меню;
- витрина по категориям, карточки вещей, размеры, лист ожидания;
- согласие на обработку данных до сохранения телефона;
- заявка на вещь или размер через бота;
- referral-механика `?start=ref<id>` и приоритет на дроп;
- lookbook, канал бренда, подбор размера;
- админ-панель: товары, статусы заявок, лист ожидания, restock, рассылки, экспорт CSV, статистика;
- все изменения каталога сохраняются в `data/catalog.json` без перезапуска.

### Mini App

- тёмная витрина с адаптацией под iOS/Android Telegram;
- hero-блок DROP 001, ticker, концепция, field lookbook и FAQ;
- поиск, категории, быстрые фильтры и сохранённые вещи;
- карточка товара с фото, материалом, посадкой, деталями и размерной сеткой;
- заявка-корзина с количеством, городом, телефоном и согласием;
- в Telegram заказ отправляется через `Telegram.WebApp.sendData()`;
- бот повторно проверяет на сервере product id, активность товара, размер, телефон и количество — цена/описание из браузера не считаются доверенными;
- в браузерном предпросмотре заказ работает как demo-flow и показывает toast вместо отправки в Telegram.

## Архитектура

```text
.
├── bot.py                    # Telegram polling, SQLite, API Mini App, админка
├── catalog.json              # seed-каталог
├── miniapp/
│   ├── index.html            # экран магазина
│   ├── styles.css            # inline-friendly визуальная система без CDN
│   ├── app.js                # каталог, корзина, Web App bridge
│   └── assets/               # demo product/editorial images
├── preview_server.py         # локальный просмотр Mini App без BOT_TOKEN
├── data/                     # создаётся при запуске; в git не попадает
├── Dockerfile
└── compose.yaml
```

Один Python-процесс отдаёт:

- `/` или `/app` — Mini App;
- `/api/catalog` — активный каталог из памяти бота;
- `/health` — health-check;
- `/assets/*` — изображения и фронтенд Mini App.

Поэтому изменения товара через `/add`, `/hide`, `/show`, `/reload` видны Mini App без второго сервиса.

## Локальный запуск Mini App

Не нужен Telegram-токен:

```bash

```

Открыть `http://localhost:4173`.

Проверка API:

```bash
curl http://localhost:4173/health
curl http://localhost:4173/api/catalog
```

## Запуск бота и Mini App

1. Создай бота в `@BotFather` и получи токен.
2. Узнай цифровые ID админов и чата менеджера.
3. Создай конфигурацию:

```bash
cp .env.example .env
```

Минимальные значения:

```env
BOT_TOKEN=...
ADMIN_IDS=123456789
MANAGER_CHAT_ID=123456789
CHANNEL_URL=https://t.me/+XufFz8GGR0o3Njky
WEBAPP_URL=https://shop.example.com
BRAND_NAME=ВОРОЖБИТОВ
PRIVACY_URL=https://example.com/privacy
```

`WEBAPP_URL` должен быть доступен по HTTPS и указывать на тот же домен/порт, где работает `bot.py`. Если оставить поле пустым, бот продолжит работать, но кнопка Mini App в меню не появится.

Запуск без зависимостей:

```bash
python3 bot.py
```

Docker:

```bash
docker compose up -d --build
```

В продакшене поставь reverse proxy с TLS перед портом `8080`, а наружу проксируй `/`, `/api/catalog`, `/assets/*` и `/health` на контейнер. Telegram не принимает обычный HTTP для Web App.

## Каталог

Рабочая копия создаётся при первом запуске:

```text
data/catalog.json
```

Сначала редактируй seed `catalog.json`, а затем удали рабочую копию только если нужно переинициализировать каталог.

Основные поля товара:

```json
{
  "id": "drop-tee-001",
  "category": "drop",
  "name": "CORE TEE / 001",
  "price": "4 900 ₽",
  "sizes": ["S", "M", "L", "XL"],
  "description": "...",
  "photo_url": "",
  "image": "assets/img/base-tee.jpg",
  "badge": "DROP 001",
  "material": "100% хлопок · 240 г/м²",
  "fit": "Свободный крой",
  "details": ["..."],
  "stock_label": "Осталось мало",
  "active": true
}
```

- `photo_url` — публичный URL для отправки фото в Telegram-боте;
- `image` — путь фронтенд-ассета Mini App;
- `active: false` скрывает вещь из бота и Mini App;
- `id` и размеры не должны содержать двоеточие: они участвуют в callback-data Telegram.

Реальные фото товара лучше загрузить в CDN/объектное хранилище, указать в `photo_url`, а локальные demo-изображения заменить в `image`.

## Фото и картинки

Все изображения витрины лежат в `miniapp/assets/img/` и собираются скриптом `tools/optimize_images.py`
(OpenCV + Pillow, без внешних сервисов):

```
python3 tools/optimize_images.py --name tag-front --src ../photos/tag-front.png \
    --crop 176,66,504,600 --denoise 5 --wb 0.7 --contrast 1.05 --saturation 0.92
```

- на выходе `<name>-{480,800,1080}.webp` + `.jpg`, `<name>.jpg` (=800, для `sendPhoto` в боте) и запись в
  `manifest.json` (размеры, srcset, LQIP-плейсхолдер 24 px в base64);
- `--isolate x,y,w,h` вырезает предмет (GrabCut) и ставит на студийный фон витрины `#0b0b0d` с тенью —
  так сделан `tag-front-studio`;
- в `catalog.json` картинка указывается одним путём (`assets/img/tag-front.jpg`); `app.js` сам подставит
  `<picture>` с WebP/JPEG и `sizes` по манифесту. Если файла нет в манифесте — покажет как обычный `<img>`;
- `"real_photos": true` у товара включает метку «РЕАЛЬНОЕ ФОТО» на карточке и подписи галереи «Лицевая / Оборот».

Реальные фото жетона и пакета — кадры с производства (скриншоты из видео 700–1000 px): их вытянули по
шуму/балансу белого и не увеличивали больше чем в 2.2 раза. Для финальной витрины нужна предметная съёмка
жетона на нейтральном фоне 2000 px+ — скрипт тот же.

## Заявка из Mini App: `POST /api/order`

`WebApp.sendData` доставляет данные боту только если приложение открыто **с reply-клавиатуры**. Из inline-кнопки,
меню бота (`/setmenubutton`) и по прямой ссылке заявка молча теряется. Поэтому витрина шлёт заявку HTTP-запросом
на тот же origin:

- заголовок `X-Telegram-Init-Data` = `Telegram.WebApp.initData`; сервер проверяет подпись HMAC-SHA256 секретом из
  токена бота (`verify_init_data`), срок `auth_date` — 24 часа; без подписи — `401`, без токена (превью) — `503`;
- тело `{"order": {...}}` в том же формате, что раньше уходил через `sendData` (`type`, `request_id`, `customer`,
  `consent`, `items[{product_id,size,quantity,note}]`); цены и названия берутся из серверного каталога;
- `note` — персонализация (номер жетона): валидируется по `personalization.pattern` товара, пишется в события
  `order_note` и в уведомление менеджеру;
- ответ `{"ok": true, "orders": [{"id","code",...}]}` → витрина показывает номер заявки; `sendData` остаётся
  запасным каналом, если эндпоинт недоступен;
- лимит тела 32 КБ; `request_id` делает повтор идемпотентным (`duplicate: true`).

## Видео дропа (hero-loop, тизер, сторис)

Подробно — в `MINIAPP-VIDEO.md`. Коротко:

- `miniapp/assets/video/hero-loop.mp4` (720×924, 17 с, без звука, 1.2 МБ) крутится в hero Mini App вместо картинки;
  при отказе автоплея (iOS) показывается постер и кнопка ▶; при `saveData` / `prefers-reduced-motion` видео не грузится.
- `miniapp/assets/video/teaser-720.mp4` (30 с, со звуком, 3.9 МБ) — карточка «FIELD NOTE 01 / ТИЗЕР» открывает его в модалке;
  там же кнопка «В СТОРИС» (`tg.shareToStory`, клиенты 7.8+).
- Бот шлёт тот же тизер новым пользователям в `/start` и в карточке товара с `"teaser": true` (`sendVideo`,
  `file_id` кешируется в таблице `kv` — файл загружается один раз).
- Статика `.mp4` отдаётся с поддержкой `Range` (206) — без этого `<video>` в Safari/WKWebView не стартует.
- URL роликов задаются в `catalog.json → media`; для сторис нужен публичный HTTPS-URL в `media.teaser_story_url`.

## Перед боевым запуском

- заменить demo-товары, цены, размеры и изображения на подтверждённые;
- проверить право на использование имени «ВОРОЖБИТОВ» и фирменных элементов;
- добавить публичную политику обработки данных и реквизиты продавца;
- подключить оплату после выбора юрлица, провайдера, возвратов и доставки;
- проверить Web App в Telegram на реальном HTTPS-домене;
- проверить, что менеджер получает город, телефон и все позиции корзины;
- настроить бэкапы `data/bot.sqlite3` и `data/catalog.json`;
- прогнать тестовую заявку на отдельном боте;
- не использовать чужие изображения людей и реальные фото без разрешения.

- Mini App должен открываться с того же HTTPS-домена, где живёт бот (`/api/order` — same-origin, CORS не настроен).
- Видео: за HTTPS-прокси отдавайте `/assets/video/` напрямую (nginx `location`/Caddy `file_server`) — Range и кеш из
  коробки, поток бота не занят раздачей; заполните `media.teaser_story_url` публичным URL, иначе «В сторис» сработает
  только когда приложение уже открыто с публичного домена.
