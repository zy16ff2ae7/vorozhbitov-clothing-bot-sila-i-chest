# Бот бренда одежды — тематическая сборка под канал ВОРОЖБИТОВ

Telegram-бот-витрина для бренда одежды. Сделан по мотивам референс-канала
(tgstat `XufFz8GGR0o3Njky`): дерзкая подача, жёсткие контекстные CTA,
постоянное ведение в канал, виральная механика «приведи друга», лист ожидания
размеров и рассылки по сегментам.

Что **взято** из референса: энергетика сообщений, БОЛЬШИЕ БУКВЫ в CTA,
эмодзи-маркеры, карусели (lookbook альбомом), высокая частота касаний,
чувство закрытого комьюнити, репост-механика для роста базы.

Что **не взято**: шок-новости, политика, аффилят-казино и крипто-боты.
Бот продаёт одежду и ничего больше.

## Что умеет

Пользователь:

- `/start` — первый вход: выбор интереса («что тебе ближе») → попадание в сегмент;
- витрина по категориям, карточка вещи с фото, ценой, размерами;
- согласие на обработку данных и рассылку — спрашивается один раз, до номера;
  отказался → номер не собираем, но каталог и канал остаются открыты;
- «Забрать размер» → заявка: номер телефона кнопкой или текстом → менеджеру;
- «Нет моего размера» → лист ожидания, уведомление при возврате;
- lookbook — альбом фотографий одним сообщением;
- «Приведи друга» — персональная ссылка `?start=ref<id>`, счётчик приглашённых,
  порог приоритета на дроп;
- контекстные CTA в конце каждого сообщения: «СМОТРЕТЬ ДРОП» / «ЗАБРАТЬ РАЗМЕР» /
  «КАНАЛ БРЕНДА».

Администратор (в личке с ботом):

- `/admin` — панель кнопками;
- `/add` — мастер добавления вещи прямо в боте: категория (или новая) → название →
  цена → размеры → описание → ссылка на фото (`/skip`, чтобы пропустить) →
  предпросмотр → публикация. Всё пишется в `catalog.json` без перезапуска;
- `/hide id` и `/show id` — убрать вещь из витрины и вернуть обратно;
- `/stats` — база, контакты, заявки, приведено друзей, лист ожидания, согласия;
- `/orders` — последние заявки с кнопками «Подтвердить», «Завершить», «Отменить»;
  при изменении статуса клиент получает автоматическое уведомление;
- `/waitlist` — кто какой размер ждёт;
- `/restock id_товара размер` — разослать «размер вернулся» по листу ожидания;
- `/broadcast текст` — черновик → выбор сегмента → предпросмотр → отправка;
- `/top` — топ по приведённым друзьям;
- `/giveaway N` — случайные победители среди набравших порог, с автоуведомлением;
- `/export` — CSV базы (с экранированием формул);
- `/reload` — перечитать `catalog.json` без перезапуска.

Сегменты рассылки: давшие согласие, только с контактом, только покупавшие,
новые без контакта, вся база, и отдельно по каждому интересу.

Рекомендуемый сегмент по умолчанию — «дали согласие». «Вся база» включает людей
без согласия: слать туда стоит только то, что вы готовы обосновать.

## Запуск

1. Создать бота в `@BotFather`, взять токен.
2. Узнать свой цифровой ID (например, `@userinfobot`).
3. `cp .env.example .env` и заполнить минимум:

```env
BOT_TOKEN=...
ADMIN_IDS=123456789
MANAGER_CHAT_ID=123456789
CHANNEL_URL=https://t.me/+ваша_ссылка_на_канал
BRAND_NAME=ВОРОЖБИТОВ
PRIVACY_URL=https://telegra.ph/politika-obrabotki-dannyh
```

4. Запустить:

```bash
/Users/mac/.workbuddy-ai/binaries/python/versions/3.13.12/bin/python3 bot.py
```

Внешних зависимостей нет — только стандартная библиотека Python 3.11+.

Docker:

```bash
docker compose up -d --build
```

На Linux перед стартом создайте каталог `data` и дайте UID 10001 права на запись
(либо замените bind mount на именованный volume).

## Каталог

Меняется двумя способами: мастером `/add` из бота (удобно на ходу, с телефона)
или ручным редактированием файла из `CATALOG_PATH` + командой `/reload`.
По умолчанию используется `data/catalog.json`: если файла ещё нет, при первом
старте бот создаёт его из демонстрационного `catalog.json`. В Docker каталог и
SQLite лежат в одном writable volume `./data`, поэтому изменения из `/add`,
`/hide` и `/show` сохраняются после пересборки контейнера.

- `categories` — `id`, `name`;
- `products` — `id`, `category`, `name`, `price`, `sizes`, `description`,
  `photo_url` (публичная HTTP(S)-ссылка или пусто), `active`;
- `lookbook` — список `{photo_url, caption}`, улетает альбомом.

`id` категорий и товаров не должны содержать двоеточие и должны быть короткими —
из них собираются `callback_data` (лимит Telegram 64 байта).

## Проверка

```bash
/Users/mac/.workbuddy-ai/binaries/python/versions/3.13.12/bin/python3 -m unittest
/Users/mac/.workbuddy-ai/binaries/python/versions/3.13.12/bin/python3 smoke_test.py
```

`smoke_test.py` прогоняет все сценарии на заглушке вместо Telegram и печатает,
что бот отправил бы в реальности.

## Перед боевым запуском

- заменить демонстрационные товары, цены и описания;
- загрузить реальные фото и вставить ссылки в `photo_url` и `lookbook`;
- вписать ссылку на канал бренда и ID менеджера;
- опубликовать политику обработки персональных данных и согласие на рассылку;
- настроить бэкап `data/bot.sqlite3` и `data/catalog.json`;
- протестировать на отдельном тестовом боте перед переводом трафика из канала.

## Честно про границы MVP

- Онлайн-оплаты нет: заявка уходит менеджеру, он подтверждает наличие и оплату.
  Подключение СБП/крипты/Stars — отдельный этап (см. ТЗ).
- Бот не определяет, подписан ли человек на канал: Telegram не отдаёт список
  подписчиков приватного канала. Можно проверить membership через
  `getChatMember`, если бот добавлен в канал администратором.
- Приём рублей и вывод в крипту — это отдельная юридическая и платёжная часть,
  требующая статуса ИП и проверки провайдера. В коде её нет.
